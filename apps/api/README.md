# apps/api

The jade-invoicing HTTP API: one Go server (ADR 0004), deployed to Vercel as the project `jade-invoicing-api`. The contract is [`openapi/openapi.yaml`](../../openapi/openapi.yaml); tooling choices are in ADR 0010.

## Requirements

- Go 1.27.3 or newer (the `go` line in `go.mod`)
- [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started) and Docker Desktop, for the database tests
- `golangci-lint` v2.15.0, for linting
- `sqlc` v1.31.1, for `go generate` (`go install github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1`; it builds without cgo, but the first build takes several minutes)

## Commands

Run from `apps/api` unless noted.

```bash
go run ./cmd/api                      # serves on :8080 (PORT overrides)
go test ./...                         # database tests skip without TEST_DATABASE_URL
go generate ./...                     # regenerate internal/api (oapi-codegen) and internal/store (sqlc)
golangci-lint run ./...
```

## Health checks

- `GET /healthz`: the process is up, and the deployed commit. Never touches the database.
- `GET /readyz`: runs `select 1` as `jade_api`; `200` when the database answers within 5 seconds, `503` otherwise. `.github/workflows/keep-alive.yml` calls it twice a day so the Supabase Free project does not pause (ADR 0013).

## Environment

| Variable | Used by | What |
|---|---|---|
| `JADE_API_DATABASE_URL` | `cmd/api` | Connection as `jade_api` through the transaction pooler. Unset: the server starts, `/healthz` works, `/readyz` answers `503`, `/v1` answers `500` |
| `DATABASE_URL` | `cmd/admin` | Connection as `postgres`. Never passed as a flag, so it stays out of shell history |
| `PORT` | `cmd/api` | Listen port, default 8080; Vercel sets it |
| `TEST_DATABASE_URL` | tests | The local stack as `postgres` |

## Creating a tenant

```bash
DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:44322/postgres go run ./cmd/admin create-tenant -name "Beispiel GmbH" -jurisdiction DE -timezone Europe/Berlin
```

JP tenants also need `-jp-tax-rounding down|up|half_up`. The command creates the tenant, an empty seller profile, and the first API key in one transaction. It prints the key once on stdout (IDs go to stderr), and only the key's SHA-256 is stored. Use synthetic names only. `go run ./cmd/admin create-tenant -h` lists the other flags.

Database tests against the local stack (from the repository root):

```bash
supabase db start
```

```bash
TEST_DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:44322/postgres go test ./...
```

## Layout

| Path | What |
|---|---|
| `cmd/api` | Entrypoint; Vercel's Go preset starts it and sets `PORT` |
| `internal/api` | Generated from the contract by `oapi-codegen`, plus a generated copy of `openapi.yaml` that the server embeds; do not edit either |
| `cmd/admin` | Operator command (`create-tenant`), runs as `postgres`; not deployed |
| `internal/httpserver` | Routes, middleware (API key auth and the per-request tenant transaction, request validation), and handlers |
| `internal/apikey` | API key format: generate, parse, hash (ADR 0012) |
| `internal/reqvalidate` | Checks requests against the embedded contract and maps failures to field errors |
| `internal/admin` | Tenant creation for `cmd/admin` |
| `internal/problem` | RFC 9457 error responses (codes in `docs/api/errors.md`) |
| `internal/db` | Postgres pool (`pgx`, exec mode) and `InTenantTx`, the transaction that sets the tenant for RLS |
| `internal/store` | Queries: SQL in `queries/`, Go generated by `sqlc` from it and `supabase/migrations` (`sqlc.yaml`); `FindAPIKey` is hand-written. The schema's acceptance tests are in `schema_test.go` |
| `internal/dbtest` | Test helpers: a pool as `postgres` for setup, and one that runs as `jade_api` |
| `internal/contracttest` | Test helper that checks responses against the contract |

## Database role

The API connects as `jade_api`, which owns nothing and is under row-level security (ADR 0007, ADR 0011). The migrations create it without a password, so no secret is in the repository. On a Supabase project, after `supabase db push`, set the password once as `postgres` with `psql`'s `\password jade_api` (it prompts, and sends only a hash), or send a SCRAM verifier you computed yourself, store it with the deployment's other secrets (locally `JADE_API_DATABASE_URL` in the ignored `.env.local`), and connect through the transaction pooler (port 6543) with the user name `jade_api.<project_ref>`.

Tests never log in as `jade_api`: they connect as `postgres` and run `SET ROLE jade_api`, which needs a direct connection such as the local stack's.
